# 错误码规范（Maintenance Assistance System）

## 响应结构

后端错误统一返回：

```json
{
  "code": 40012,
  "msg": "文件解析失败",
  "message": "文件解析失败",
  "detail": {},
  "trace_id": "xxxx",
  "data": null
}
```

- `code`：业务错误码（前端主判断字段）
- `msg/message`：错误文案
- `detail`：补充信息（如失败文件列表）
- `trace_id`：链路追踪 ID（响应头也会返回 `X-Trace-Id`）

## 成功码

- `1`：成功

## 通用错误码

- `40000`：请求参数错误
- `40100`：未授权 / 登录失效
- `40300`：无权限
- `40400`：资源不存在
- `50000`：服务器内部错误

## 文档与解析

- `40010`：文件类型不支持
- `40011`：请求核心参数无效
- `40012`：文件解析失败
- `40013`：文件内容超长（token 超限）
- `40410`：文档资源不存在

## 认证与用户

- `40110`：用户名或密码错误
- `40111`：登录身份非法
- `40310`：所选身份与账号角色不匹配
- `40311`：账户不可用
- `40420`：用户不存在
- `40020`：手机号已被占用
- `40021`：邮箱已被占用
- `40022`：用户名已存在

## 审核与会话

- `40030`：审核单已处理（幂等保护）
- `40430`：对话不存在
- `40330`：无权访问该对话
- `40040`：消息上下文过长

## 前端使用约定

- 不再依赖后端返回的 `message` 字符串做分支判断。
- 统一按 `code` 映射用户提示文案。
- 可使用 `detail.files` 显示解析失败文件明细（例如 `DOC_PARSE_FAILED` / `DOC_TOKEN_LIMIT_EXCEEDED`）。
