文件处理流程 + 问答回复流程

当前系统工作流总览，覆盖上传、解析、审核、向量化、检索和大模型回复。

FastAPI MySQL + SQLAlchemy MinerU / PyMuPDF Visualized_BGE Milvus OpenAI Compatible LLM

文件处理流程

01上传源文件
前端通过 FormData 上传，后端只保存源文件并登记来源，不直接写正式文档库。
POST /api/v1/document/upload_files FastAPI UploadFile aiofiles
02源文件记录
文件保存到 source_documents 目录，同时写 SourceDocument，状态为 uploaded。
upload/source_documents SourceDocument MySQL
03解析分流
按文件类型进入不同解析器，抽取文本、表格和有效图片，过滤 logo、底图等装饰内容。
PDF: PyMuPDF + MinerU OCR
PPT: LibreOffice 转 PDF + MinerU / python-pptx
HTML: BeautifulSoup + Selenium
Word/TXT/Markdown/Excel/Image: 专用 Parser
04AI 结构化整理
将非结构化内容整理成系统字段：标题、问题简介、原因、评估、检查、解决方案、关键要点和图片归属。
OpenAI Chat Completions MODEL_AI JSON 结果解析
05提交审核
技术人员提交审核稿，管理员在审核页面通过或驳回。
Document_review KnowledgeDocumentReview status=review_pending
06正式入库
审核通过后写入正式文档表；知识库文档额外维护章节表。
DocumentBreakdown DocumentKnowledge KnowledgeDocumentSection
07向量化
生成主 chunk、字段 chunk、章节 chunk、表格 chunk，超长内容按 Milvus 字段限制拆分。
VectorService VectorStoreMultimodal Visualized_BGE PyTorch CPU/CUDA
08写入向量库
向量写入成功后，文档标记 is_vectorized=1，源文件状态改为 vectorized。
Milvus documents_collection_main_chunk IP + IVF_FLAT
!失败保护
审核通过阶段如果向量化失败，事务回滚，不把审核状态改为通过，返回具体失败原因。
DB rollback Milvus cleanup 失败原因弹窗

问答回复流程

01创建会话
用户创建聊天会话，后端写 Conversation 并绑定当前用户。
POST /api/v1/chats/{chat_id}/session Conversation
02发送问题
用户提交问题，可携带问答图片；后端保存用户消息并统计 token。
POST /api/v1/chats/{chat_id}/completions Message role=user
03图片语义增强
如有图片，先调用视觉模型生成图片描述，再和用户问题一起用于检索。
POST /api/v1/chats/{chat_id}/images describe_image MODEL_AI
04向量检索
查询文本和图片进入 BGE 多模态嵌入，检索 Milvus 中最相似的 chunk。
VectorService.search_similar_documents Visualized_BGE Milvus search
05候选聚合与回查
按 doc_id 和 library_type 合并命中 chunk，过滤低分与已删除文档，补全标题、章节和图片。
similarity_low_limit 关键词补召回 MySQL 回查
06构造 RAG Prompt
知识库取命中 chunk 附近章节，故障库拼接七段字段，并加入最近历史消息和参考图片。
get_prompt generate_messages MESSAGE_MAX_TOKEN
07生成回答
调用 OpenAI 兼容的大模型接口，支持流式 SSE 或普通响应。
OpenAI Chat Completions StreamingResponse SSE
08返回与持久化
回答脱敏，参考图片统一转 /upload/... URL 后展示，并保存 AI 消息和引用文档。
Message role=assistant ai_reference_doc_ids reference_docs
核心约束
  • 源文件、审核稿、正式文档、向量库是分阶段状态流转，不能跳过审核和向量一致性检查。
  • 审核通过时向量化失败会回滚，避免正式文档表和 Milvus 出现一对一不一致。
  • 问答回复只基于检索到的知识文档组织证据，最终图片由后端统一追加，避免模型输出本地路径。
